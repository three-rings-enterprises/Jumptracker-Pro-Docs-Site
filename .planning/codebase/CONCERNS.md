# Codebase Concerns

**Analysis Date:** 2026-09-30

Scope: this repo is an Astro + Starlight documentation site (`astro.config.mjs`, `src/content/docs/**`). It has no application code, no tests, and no runtime secrets. Most concerns are content accuracy, missing automation, and repository hygiene rather than code defects.

## Tech Debt

**Content is not verified against the app in any automated way:**

- Issue: Docs describe behavior of a separate codebase (`/Users/josephpascucci/GitHub/JumpTracker-Pro-App`, per `AGENTS.md`). Nothing detects drift when the app changes (UI labels such as **Log Day**, **Edit Day**, **Import CSV**, **View Import History**; service types; invoice grouping).
- Files: `src/content/docs/technical/how-totals-are-calculated.md`, `src/content/docs/technical/import-burble-logbook.md`, `src/content/docs/case-studies/log-your-day-with-check-in.md`, `src/content/docs/start/welcome.md`
- Impact: Published guides can silently become wrong after an app release. Screenshots in `src/assets/**` will go stale when the UI changes.
- Fix approach: Add a "last verified against app version X" front-matter field (extend the schema in `src/content.config.ts` using `docsSchema({ extend: ... })`) and review it on each app release. Keep the absolute path in `AGENTS.md` as the source of truth, but note it is machine-specific (see Fragile Areas).

**Unresolved editorial note published in a live page:**

- Issue: `src/content/docs/technical/how-totals-are-calculated.md` ends with an italic line: "Reviewed against the app's invoice reporting documentation. Check the wording against the current app before publishing." This is an internal reviewer note that renders to readers.
- Files: `src/content/docs/technical/how-totals-are-calculated.md` (last line)
- Impact: Readers see a draft-status note; signals the page is unverified.
- Fix approach: Verify wording against the app, then delete the line (or move it to an HTML comment / front-matter field).

**Hard-coded sidebar sections and cross-page links:**

- Issue: `astro.config.mjs` defines three autogenerated sidebar groups (`start`, `technical`, `case-studies`). Internal links are hand-written absolute paths (for example `/technical/import-burble-logbook/` in `src/content/docs/case-studies/log-your-day-with-check-in.md`, `/start/welcome/` in `src/content/docs/index.mdx`). Renaming or moving a file breaks links with no build-time error.
- Files: `astro.config.mjs`, `src/content/docs/index.mdx`, `src/content/docs/start/welcome.md`, `src/content/docs/case-studies/log-your-day-with-check-in.md`
- Impact: Broken links after slug renames; sidebar order is alphabetical by filename unless `sidebar.order` front matter is added (none is set), so ordering is accidental.
- Fix approach: Add `starlight-links-validator` (or equivalent) to the build; set `sidebar: { order: N }` in front matter where order matters.

**Third-party GSD/agent tooling committed in bulk:**

- Issue: ~1,650 tracked files, the large majority being agent tooling (`.claude/gsd-core/` 608 files, `.codex/gsd-core/` 608 files, `.claude/commands/` 72, `.codex/skills/` 72, `.claude/agents/` 64, `.codex/agents/` 99, plus hooks and scripts; ~14 MB in `.claude`, ~15 MB in `.codex`). `skills-lock.json` references BMAD skills. The actual site is ~20 tracked files.
- Files: `.claude/`, `.codex/`, `skills-lock.json`, `.claude/gsd-file-manifest.json`, `.claude/gsd-install-state.json`
- Impact: Noisy diffs and PRs when tooling is updated; duplicated content across `.claude` and `.codex`; repo clone size dominated by tooling; `git add -A` (the documented workflow in `docs/git-workflow.md`) will sweep up any tooling changes into doc PRs.
- Fix approach: Decide whether tooling belongs in version control. If not, add `.claude/gsd-core`, `.codex`, etc. to `.gitignore` and re-install on demand; if yes, keep tooling updates in dedicated commits (`chore:`), never mixed with `docs:` commits.

## Security Considerations

**Screenshots may expose personal or real financial data:**

- Risk: Images are user-supplied phone screenshots with status bars (time, battery, signal) and real-looking earnings/load data (for example `$405.00` balance, `09/13/2026` transactions in `src/assets/import-burble/burble-download-transaction-history.png`; tip/pay values visible behind the keyboard in `src/assets/log-with-check-in/step-3-2-day-notes.png`). Dropzone names, load identifiers (`PAC 750 n`), and personal names could appear in other captures.
- Files: `src/assets/import-burble/*`, `src/assets/log-with-check-in/*`
- Current mitigation: None detected (no review checklist).
- Recommendations: Review every screenshot before commit for names, emails, dropzone identities, and real earnings; use demo accounts when capturing; crop status bars and keyboards. Strip EXIF metadata from `.jpg` files.

**Agent hooks and permissions committed to the repo:**

- Risk: `.claude/settings.local.json` is tracked and wires ~15 hook commands (Node scripts under `.claude/hooks/`) that execute on every tool use; `settings.local.json` is conventionally personal/untracked. Commands resolve `node` from fixed paths (`/opt/homebrew/bin/node`, `/usr/local/bin/node`).
- Files: `.claude/settings.local.json`, `.claude/hooks/*`
- Current mitigation: Hooks include guards (`gsd-secret-read-guard.js`, `gsd-prompt-guard.js`) but are themselves third-party code executed on contributors' machines.
- Recommendations: Move local settings out of version control (add `.claude/settings.local.json` to `.gitignore`); review hook scripts on each tooling update.

**Environment files only partially ignored:**

- Risk: `.gitignore` lists `.env` and `.env.production` only; variants such as `.env.local` or `.env.development` are not ignored. No `.env*` files exist today.
- Files: `.gitignore`
- Recommendations: Replace with `.env*` plus `!.env.example`.

## Performance Bottlenecks

**Large, unoptimized screenshot sources:**

- Problem: `src/assets/log-with-check-in/step-3-2-day-notes.png` is ~660 KB (1206x2622); the set of check-in screenshots totals ~1.5 MB and Burble set ~600 KB.
- Files: `src/assets/log-with-check-in/*.png`, `src/assets/import-burble/*`, `src/styles/custom.css`
- Cause: Full-resolution phone screenshots are displayed at max 320px wide (`.sl-markdown-content img { max-width: min(100%, 320px) }`).
- Improvement path: Images under `src/assets/` referenced via relative Markdown paths are processed by Astro/`sharp` at build time (responsive output, WebP/AVIF), so runtime impact is modest; still, crop and compress sources (for example `pngquant`) to keep the repo small. Note the CSS also caps the width of every content image, including any future diagrams or wide screenshots; scope it with a class if wider images are needed.

## Fragile Areas

**Machine-specific absolute path to the app repo:**

- Files: `AGENTS.md` (symlinked as `CLAUDE.md`)
- Why fragile: Points at `/Users/josephpascucci/GitHub/JumpTracker-Pro-App`. The docs repo itself lives under `/Users/josephpascucci/Documents/GitHub/`, so the two checkouts are in different parent directories and the path breaks on any other machine or contributor.
- Safe modification: Use a relative or `~`-based path, or document an env var. Keep `CLAUDE.md` as a symlink to `AGENTS.md` (a Windows checkout without symlink support will break it).

**`AGENTS.md` contains unrelated template guidance:**

- Files: `AGENTS.md`
- Why fragile: Links to Tailwind, i18n, framework-component guides though the project uses none of them. Agents may add dependencies or patterns the site does not need.
- Safe modification: Trim to the guides that apply (routing, content collections, Starlight).

**Dependency and runtime versions unpinned:**

- Files: `package.json`, `package-lock.json`
- Why fragile: Dependencies use caret ranges (`astro ^7.2.10`, `@astrojs/starlight ^0.42.4`, `sharp ^0.35.3`). Starlight is pre-1.0, so minor bumps can be breaking. Installed Astro is 7.3.5 (above the declared floor), requiring Node >=22.12.0 (per `node_modules/astro/package.json`), but there is no `engines` field, `.nvmrc`, or `.node-version`. Local Node is v26.0.0.
- Safe modification: Add `"engines": { "node": ">=22.12.0" }` and a `.nvmrc`; raise declared ranges to match the locked versions; upgrade Starlight deliberately and run `npx astro build` after.

**Nested image path convention:**

- Files: `src/content/docs/**/*.md`
- Why fragile: Images are referenced with `../../../assets/<folder>/<file>` relative paths from pages two levels deep. Moving a page to a different depth breaks every image reference silently until build.
- Safe modification: Keep the page-depth convention (`src/content/docs/<section>/<page>.md`) and verify with `npx astro build`.

**Generated `.astro/` directory and empty staging folder:**

- Files: `.astro/` (gitignored), `temporary assets/` (empty, untracked, name contains a space)
- Why fragile: `temporary assets/` has no purpose documented and is not ignored; if screenshots are dropped into it they could be accidentally committed unprocessed.
- Safe modification: Delete it or add to `.gitignore`; use a name without spaces.

## Scaling Limits

**Manual content and navigation model:**

- Current capacity: 4 content pages (`start/welcome.md`, `technical/how-totals-are-calculated.md`, `technical/import-burble-logbook.md`, `case-studies/log-your-day-with-check-in.md`) plus the splash `index.mdx`.
- Limit: Alphabetical autogenerated sidebars and hand-maintained `LinkCard`s in `src/content/docs/index.mdx` (each card links to a single page, e.g. Technical Guides links only to `how-totals-are-calculated`) do not scale; the landing page needs editing per section.
- Scaling path: Link cards to section index pages, add `sidebar.order` front matter, and use Starlight's built-in Pagefind search (already enabled by default).

## Dependencies at Risk

**`sharp` native binary:**

- Risk: `sharp ^0.35.3` is a native dependency; image build fails if the install platform lacks a prebuilt binary or on an unsupported Node version.
- Impact: `astro build` fails at the image-processing step on new CI/host images.
- Migration plan: Pin Node version in the host config; Astro's squoosh-free defaults require `sharp`, so keep it.

**Pre-1.0 Starlight:**

- Risk: `@astrojs/starlight` `0.x` has no semver stability guarantee.
- Impact: Config keys in `astro.config.mjs` (`logo`, `customCss`, `sidebar.autogenerate`) and CSS variables in `src/styles/custom.css` (`--sl-color-accent-*`) may change between minors.
- Migration plan: Read release notes before bumping; test with `npx astro build` and a visual check of light and dark themes.

## Missing Critical Features

**No CI, build validation, or deployment config:**

- Problem: No `.github/` workflows, no Netlify/Vercel/Cloudflare config, no deploy documentation. `docs/git-workflow.md` itself says "Check whether `main` triggers a deploy", confirming the deploy path is unknown. `astro.config.mjs` sets `site: 'https://docs.jumptrackerpro.com'`, so a host exists or is planned.
- Blocks: Automated `astro build`/link/type checks on PRs; predictable publishing; the squash-merge workflow cannot verify that `main` builds.
- Fix approach: Add a GitHub Actions workflow running `npm ci && npx astro check && npx astro build` on PRs; document the hosting and deploy trigger in `docs/git-workflow.md`.

**No `astro check` / TypeScript tooling dependency:**

- Problem: `tsconfig.json` extends `astro/tsconfigs/strict`, but `@astrojs/check` and `typescript` are not in `package.json`, so `astro check` cannot validate front matter or content schema errors beyond what `astro build` reports.
- Fix approach: `npx astro add check` (adds `@astrojs/check` and `typescript`) and add a `check` script.

**No 404, SEO, or feedback channel configuration:**

- Problem: `src/content/docs/start/welcome.md` tells readers "let us know" about missing/wrong content but provides no contact link, issue tracker, or `editLink` in the Starlight config. There is no `social`, `lastUpdated`, or `editLink` in `astro.config.mjs`.
- Fix approach: Add `editLink.baseUrl` pointing at the GitHub repo, `lastUpdated: true`, and a support email/issue link on the welcome page.

**Incomplete documentation coverage:**

- Problem: The welcome page advertises invoices, locations, Settings, earnings tracking, and the in-app tour, but no guides exist for them (only totals, Burble import, and check-in case study). `README.md` is two lines with no setup or contribution instructions.
- Fix approach: Add guides for invoices and location/service setup; expand `README.md` with `npm install`, `npm run dev`, `npm run build`, and a link to `docs/git-workflow.md`.

## Test Coverage Gaps

**No tests or validation of any kind:**

- What's not tested: Build success, internal links, image references, front-matter schema, spelling, accessibility (alt text exists on images, but nothing enforces it).
- Files: entire repo; no test runner, lint, or formatter configs (`package.json` scripts: `dev`, `start`, `build`, `preview`, `astro`).
- Risk: Broken builds or links reach `main` unnoticed. The recent commit "Remove obsolete test files" (`0194750`) removed prior test artifacts, leaving no checks.
- Priority: Medium. Start with a CI build plus link validation; add `cspell` and Prettier only if content volume grows.

**Git workflow relies on `git add -A` and force-push:**

- What's not guarded: `docs/git-workflow.md` instructs `git add -A` and `git push --force-with-lease origin develop` after each squash merge. Combined with the large tracked tooling tree and untracked `temporary assets/`, this risks committing unintended files; there are no branch protections documented.
- Files: `docs/git-workflow.md`
- Priority: Low to Medium. Prefer explicit `git add src docs` paths and enable GitHub branch protection on `main`.
