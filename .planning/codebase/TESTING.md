# Testing Patterns

**Analysis Date:** 2026-09-30

## Test Framework

**Runner:**

- None. No test runner (Jest, Vitest, Playwright, Cypress) is installed or configured. `package.json` has no `test` script and no test dependencies (only `@astrojs/starlight`, `astro`, `sharp`).
- No `*.test.*` or `*.spec.*` files exist outside tooling directories (`.claude/`, `.codex/`). A prior commit removed obsolete test files (`0194750 Remove obsolete test files and update git workflow documentation`).

**Assertion Library:** Not applicable.

**Run Commands (actual verification tools):**

```bash
npx astro build        # Full static build; fails on invalid frontmatter, broken image imports, MDX errors
npx astro dev          # Local dev server with hot reload (npm run dev / npm start)
astro dev --background # Preferred per AGENTS.md; manage with `astro dev status|logs|stop`
npx astro preview      # Serve the built dist/ output (npm run preview)
```

The VS Code launch config `.vscode/launch.json` ("Development server") runs `./node_modules/.bin/astro dev`.

## Test File Organization

**Location:** Not applicable. If tests are introduced, place them in a top-level `tests/` directory (not inside `src/content/`, since Starlight's `docsLoader()` treats everything in `src/content/docs/` as a page).

**Naming:** If added, use `*.test.ts`.

## Test Structure

No suites exist. Verification is manual plus build-time:

1. Write or edit the page in `src/content/docs/<section>/`.
2. Run `astro dev --background` and view the page in a browser; check both the dark and light themes (`src/styles/custom.css` defines separate color blocks).
3. Check the page on a narrow (phone) viewport; screenshots are capped at 320px wide by `.sl-markdown-content img`.
4. Confirm the page appears in the sidebar section (autogenerated from folder in `astro.config.mjs`) and is found by the search box.
5. Click every internal link (`/section/page/` form) and confirm images render.
6. Run `npx astro build` and confirm it completes with no errors or warnings.
7. Verify feature claims against the app at `/Users/josephpascucci/GitHub/JumpTracker-Pro-App` (see `AGENTS.md`).

## Mocking

Not applicable. No code with external dependencies is tested.

## Fixtures and Factories

**Test Data:** None. Screenshots used as documentation assets live in `src/assets/<page-slug>/`. `temporary assets/` (repo root, currently empty) is a staging folder for unprocessed screenshots; move finished images into `src/assets/<page-slug>/` and remove staging files before committing.

## Coverage

**Requirements:** None enforced. No CI configuration detected (no `.github/workflows/`); `docs/git-workflow.md` notes to check whether `main` triggers a deploy and to "Test locally before opening the PR: `npx astro dev` or `npx astro build`."

**View Coverage:** Not applicable.

## Test Types

**Unit Tests:** Not used. There is no custom logic (only `src/content.config.ts` and `astro.config.mjs`).

**Integration Tests:** Not used. The build (`npx astro build`) is the de facto integration check: it validates the content collection schema (`docsSchema()` in `src/content.config.ts`), resolves image imports, and generates the Pagefind search index and sidebar.

**E2E Tests:** Not used.

## Common Patterns

**Pre-PR checklist (substitute for automated tests):**

```bash
npx astro build        # must exit 0
git diff --stat        # confirm only intended files changed (no stray files from `temporary assets/`)
```

Then follow the ship flow in `docs/git-workflow.md` (PR `develop` -> `main`, squash merge).

**Broken-link and image check:** there is no automated link checker. If one is wanted, add `starlight-links-validator` as a Starlight plugin in `astro.config.mjs` so `astro build` fails on dead internal links; this is the recommended first automated check for this repo.

**Recommended additions if automation is introduced:**

- `astro check` (add `@astrojs/check` and `typescript`) for type/content diagnostics via `npx astro check`.
- A `"test"` script in `package.json` that runs `astro build` (plus link validation) so CI and contributors have one command.
- GitHub Actions workflow in `.github/workflows/` running `npm ci && npm run build` on pull requests to `main`.

## Gaps to Be Aware Of

- Factual accuracy of content is not machine-checked. Pages such as `src/content/docs/technical/how-totals-are-calculated.md` carry an explicit "check the wording against the current app" note, meaning verification against the app is still pending for that page.
- Typos and broken relative image paths are only caught by reading the page or by the build (images) and are not caught for prose.
